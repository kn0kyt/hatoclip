# Hatoclip 設計メモ

> 名称：Hatoclip（ハトクリップ）。伝書鳩がクリップボードを届けるイメージで、アイコンや UI の文言も鳩モチーフで統一している。

この文書は Hatoclip v1.0.0 の実装に沿った設計メモです。利用者向けの説明は [README](../README.md)、iOS ショートカットの作り方は [shortcut.md](shortcut.md) にあります。

## 1. 概要

iPhone（およびスマホ全般）と Windows PC の間で、クリップボードのテキストを同じ Wi-Fi 内でやり取りする Windows 常駐アプリ。

- スマホ側はアプリ不要。PC に表示された QR コードを読み取り、ブラウザで開くページから送受信する
- よく使う人向けに、iOS ショートカットからワンアクションで送受信できる API を持つ（任意設定）
- 通信は LAN 内のみ。外部サーバーとは一切通信しない
- 作者以外（家族など）にも exe を渡して使ってもらう前提で、各 PC で設定ゼロで動く

## 2. 設計方針

| 方針 | 理由・具体策 |
|---|---|
| 管理者権限を一切要求しない | 配る相手の PC で UAC を出さない。待ち受けは `HttpListener` ではなく Kestrel（`HttpListener` は LAN 待ち受けに URL 予約＝管理者権限が要る）。自動起動は `HKCU` の Run キー |
| 外部ネットワークと通信しない | テレメトリ、更新チェックなし。Web ページも exe に埋め込み、CDN などは使わない |
| システム設定を変更しない | ファイアウォールやネットワークの種類は読み取って診断を表示するだけで、変更は利用者に案内する |
| 設定ゼロで動く | 初回起動でキー生成・設定ファイル作成・QR ウィンドウ表示まで自動。LAN の IP も自動選択 |
| 依存は最小限 | NuGet パッケージは本体が QRCoder（MIT）のみ、テストが xunit.v3 のみ。ASP.NET Core は共有フレームワーク（`FrameworkReference`）として使う。Web ページはフレームワーク不使用の素の HTML/CSS/JS |
| 秘密を残さない | 接続キーとクリップボードの内容はログに出さない。キーは URL フラグメントで渡し、サーバーのリクエストログにも載らない |
| 機能ごとにクラスを分ける | HTTP サーバー・認証・UI・診断を分離し、将来の機能（後述のサブディスプレイなど）でサーバーと認証の土台を流用できるようにする |

## 3. 技術スタック

- C# / .NET 10（`net10.0-windows`）、WinForms（`NotifyIcon` によるタスクトレイ常駐）
- ASP.NET Core Kestrel を同一プロセスに組み込み（`<FrameworkReference Include="Microsoft.AspNetCore.App" />`、`WebApplication.CreateSlimBuilder`）
- QR コード生成：QRCoder 1.8.0（誤り訂正レベル M）
- Web ページ（HTML/CSS/JS/manifest/アイコン）は埋め込みリソースとして exe に同梱
- テスト：xUnit v3（Microsoft.Testing.Platform で実行。`global.json` で有効化）
- 対応 OS：Windows 10 / 11（x64 / arm64）

## 4. 全体構成

### 4.1 プロセスとスレッド

1 プロセスで次のスレッドが動く。

- **UI スレッド（STA）**：WinForms のメッセージループ。トレイアイコン、QR ウィンドウ、ダイアログ、**クリップボード操作**はすべてここで行う
- **Kestrel のスレッド**：HTTP リクエストを処理する。クリップボードに触れるときは `UiDispatcher`（UI スレッドで作った隠し `Control` への `BeginInvoke`）で UI スレッドにマーシャリングし、`Task` として待つ。WinForms の `Clipboard` は STA スレッドからしか使えないため
- **接続状態の再計算**：`ConnectionMonitor` がバックグラウンドのタスクで IP・診断を計算し、結果だけを UI スレッドに渡す（重い処理で UI を止めない。同時要求はまとめる）
- **多重起動の待ち受け**：2 つ目の起動からの通知を待つバックグラウンドスレッド

起動順：多重起動チェック → ログ開始・古いログ削除 → 設定読み込み → `UiDispatcher` 作成 → サーバー起動 → トレイ常駐 → メッセージループ。終了時はサーバーを停止してポートを解放する（停止は最大 5 秒待つ）。

## 5. 認証と接続キー

- キーは初回起動時に暗号論的乱数で 128 bit を生成し、小文字 16 進 32 文字として `config.json` に保存する
- API（`/api` 以下）はすべてキー必須。ヘッダー `X-Hatoclip-Key` で受け取り、`CryptographicOperations.FixedTimeEquals` で定数時間比較する。キーはリクエストごとに設定から読むので、再生成は再起動なしで即時に効く
- **キーを URL フラグメントで渡す**：QR の URL は `http://<PCのLAN IPv4>:<port>/#k=<key>`。フラグメントはブラウザがサーバーに送らないので、キーがリクエスト行やログに残らない。ページの JS がフラグメントからキーを読んで保存し、`history.replaceState` でアドレスバーと履歴から消す
- **カスタムヘッダーで認証する理由**：Cookie やクエリ文字列と違い、ブラウザが自動で付けることがない。別オリジンのページが `X-Hatoclip-Key` を付けて送るには CORS のプリフライトが必要だが、サーバーは CORS に対応していない（OPTIONS には CORS ヘッダーなしの 204 を返す）ため、プリフライトが通らない。これで CSRF と DNS リバインディング経由の操作も防ぐ（攻撃側のページはキーを知らず、知っていてもヘッダーを付けられない）
- 認証は `/api` のルートグループ全体にメタデータで掛けている。後から追加したエンドポイントにも自動で掛かる
- `/api` の未知のパスは、キーが無ければ 401、キーが正しければ 404。キーを持たない相手にはどのパスが存在するかも分からない

### 5.1 簡易レート制限（`AuthRateLimiter`）

| 項目 | 値 |
|---|---|
| ブロックするまでの失敗回数 | 同じ IP から 10 分以内に 10 回 |
| ブロック期間 | 10 分（その間、間違ったキーには 429） |
| 追跡する IP 数の上限 | 10,000（期限切れのものは 1 分ごとに整理、超えたら最古を削除） |

- **正しいキーは常に通す**：キーの検証を先に行うので、ブロック中の IP（同じ NAT の裏の別端末が間違えた場合など）からでも正しいキーなら成功する。成功すると失敗回数は消えるが、進行中のブロックは間違ったキーに対して残る
- ブロック中の間違ったキーは 429 を返し、失敗回数には数えない
- OPTIONS は認証失敗として数えない
- IPv4 射影 IPv6 アドレスは IPv4 と同じ扱い
- キーを再生成すると、失敗履歴とブロックをすべて消す
- 状態はメモリのみ（再起動で消える）

### 5.2 キーの再生成

トレイメニューの「接続キーを再生成...」または QR ウィンドウの「キーを再生成」から行う。確認ダイアログ（既定ボタンは「いいえ」）で「接続キーを再生成すると、今までに接続したスマホはすべて接続できなくなります。再生成しますか？」と表示する。保存に失敗した場合は元のキーに戻す（メモリとファイルを一致させる）。再生成後は QR ウィンドウが新しい URL に更新される。

## 6. HTTP API

### 6.1 待ち受け

- `0.0.0.0:<port>` の **IPv4 のみ**で待ち受ける（`ListenAnyIP` だと `[::]` のデュアルモードになり IPv6 も受けるため、`Listen(IPAddress.Any, port)` を使う）
- ソケットは `ExclusiveAddressUse`（`SO_EXCLUSIVEADDRUSE`）で bind する。(a) 他のプロセスが使っているポートを確実に bind 失敗にして次のポートへ進めるため（Windows はワイルドカードのポートを一部共有できてしまう）、(b) 実行中に他のプロセスが同じポートに割り込めないようにするため
- 既定ポートは `52817`。使えない場合（使用中、または Hyper-V/WSL/Docker の除外範囲でアクセス拒否）は、その上の番号を最大 20 個まで順に試す。**代わりのポートはその回だけ使い、設定には保存しない**。次回起動時はいつものポートを試すので、衝突が解消すればブックマークやショートカットがそのまま使える
- `Server` ヘッダーは出さない

### 6.2 エンドポイント

| メソッド | パス | 認証 | 内容 |
|---|---|---|---|
| GET/HEAD | `/`, `/index.html` | 不要 | 送受信ページ |
| GET/HEAD | `/app.js`, `/style.css` | 不要 | スクリプト、スタイル |
| GET/HEAD | `/manifest.webmanifest`, `/icon.png`, `/icon-192.png`, `/apple-touch-icon.png`, `/favicon.ico` | 不要 | PWA・アイコン（favicon はトレイと同じ鳩） |
| GET | `/api/ping` | 必要 | 接続確認。`{"ok":true,"pcName":"…","shortcutSendUrl":"…","shortcutReceiveUrl":"…"}` |
| POST | `/api/clipboard` | 必要 | 本文のテキストを PC のクリップボードに入れる。`{"ok":true,"length":<文字数>}` |
| GET | `/api/clipboard` | 必要 | PC のクリップボードのテキストを返す。`{"ok":true,"text":"…","type":"text"}` |

- 静的ファイルは上の一覧にあるものだけを返し、それ以外は 404
- `pcName` は `Environment.MachineName`。ショートカットの 2 つの URL は設定ファイルの値で、絶対 URL の http/https 以外は `""` にして返す
- POST は `application/json`（`{"text":"…"}`。`+json` の型も JSON 扱い）と、それ以外（`text/plain` など）を UTF-8 のテキストとして受け付ける（先頭の BOM は除く）。iOS ショートカットからは JSON、ページからは `text/plain` で送る
- `length` は .NET の文字列長（UTF-16 単位）
- 本文が空のときは PC のクリップボードを消さないよう 400 を返す（クリップボードが空の状態でショートカットを実行した場合など）
- テキストのみ対応。GET でクリップボードにテキスト以外しか無いときは `"text":""`、`"type":"non-text"`。クリップボードが空なら `"text":""`、`"type":"text"`
- GET が成功すると PC 側でトレイアイコンを切り替える（7.1）
- 正しいキーでの `/api/ping` が成功すると、サーバーは内容を持たないイベント（`Pinged`）を出し、QR ウィンドウが表示中なら「✓ スマホが接続しました」を出す（7.3）。ページは読み込み時と再接続のたびに ping する

### 6.3 ステータスコード

エラー時の本文は `{"ok":false,"error":"<コード>"}`。

| ステータス | `error` | 条件 |
|---|---|---|
| 200 | — | 成功 |
| 204 | — | `/api` 以下への OPTIONS（本文なし、CORS ヘッダーなし） |
| 400 | `bad-request` | JSON が壊れている、オブジェクトでない、`text` が文字列でない |
| 400 | `empty` | テキストが空 |
| 401 | `unauthorized` | キーが無い、または一致しない |
| 403 | `get-disabled` | 「スマホからの取得を許可」が無効なときの GET `/api/clipboard` |
| 404 | `not-found` | キーは正しいが `/api` の未知のパス（静的ファイルの 404 は本文なし） |
| 413 | `too-large` | 本文が 1 MB（1,048,576 バイト）を超える。`Content-Length` で先に判定し、無い場合も読みながら打ち切る |
| 429 | `too-many-requests` | ブロック中の IP からの間違ったキー |
| 503 | `clipboard-busy` | 他のアプリがクリップボードを開いたままで、リトライしても使えない |
| 500 | `internal-error` | 想定外の例外（内容はログに記録） |

クリップボードが他のアプリにロックされている場合（`ExternalException`）は、80 ms 間隔で最大 5 回試してから 503 にする。待つ間は UI スレッドを塞がない。

### 6.4 セキュリティヘッダーとキャッシュ

すべての応答（エラー応答を含む）に付ける。

- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: no-referrer`
- `Content-Security-Policy: default-src 'self'; style-src 'self' 'unsafe-inline'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`
  - スクリプトは `/app.js` のみ（インラインスクリプトなし）。`style-src` の `'unsafe-inline'` は、インライン SVG の鳩の `style="fill: var(…)"` のため（プレゼンテーション属性では CSS 変数が使えず、`<use>` の複製を `style.css` から確実に塗り分けられない）
- キャッシュ：`/api` 以下は `Cache-Control: no-store`、静的ファイルは `no-cache`（exe を更新したら次の読み込みで新しいページになる）

## 7. PC 側

### 7.1 タスクトレイ

起動するとタスクトレイに常駐する。アイコンのダブルクリックで QR ウィンドウを開く。ツールチップは `Hatoclip – http://<IP>:<port>`（キーは含めない）。

メニュー（上から）：

| 項目 | 動作 |
|---|---|
| 接続用QRコードを表示（太字） | QR ウィンドウを開いて前面に出す |
| ─ | |
| Windows起動時に自動起動 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` の `Hatoclip` 値の登録・削除。チェック状態はメニューを開くたびにレジストリから読む |
| スマホからの取得を許可 | `allowGet`。外すと GET `/api/clipboard` が 403 |
| 通知に内容を表示 | `showPreview` |
| 履歴と同期に残さない | `excludeFromHistory` |
| 接続キーを再生成... | 5.2 |
| ─ | |
| 終了 | サーバーを止めて終了 |

設定の切り替えはその場で `config.json` に保存され、次のリクエストから効く。

**アイコンの 3 状態**（`src/Hatoclip/assets/` の .ico を差し替えれば変更できる。`tools/make-tray-icons.ps1` で生成）：

| 状態 | ファイル | 表示 |
|---|---|---|
| 待機中 | `hatoclip.ico` | 鳩の横顔シルエット（exe・ウィンドウ・favicon も同じ） |
| 受信直後 | `hatoclip-received.ico` | オレンジの封筒付き。3 秒で待機中に戻る |
| スマホが取得した直後 | `hatoclip-sent.ico` | 青緑の矢印付き。3 秒で待機中に戻る。通知は出さない |

取得時にもアイコンを変えるのは、漏れたキーで PC のクリップボードを読まれた場合に気付けるようにするため。タイマーは 1 つで、最後の出来事から 3 秒後に待機中に戻る。

**受信通知**：テキストを受信するとバルーンを 3 秒（指定値）表示する。タイトル「Hatoclip」、本文「鳩がテキストを届けました」。「通知に内容を表示」が有効（既定）なら 2 行目にプレビューを付ける。プレビューは改行・タブを空白にまとめ、先頭 40 書記素（絵文字を途中で切らない）で切って「…」を付ける。空白だけのテキストは「（空のテキスト）」。

**クリップボード履歴・クラウド同期からの除外**：「履歴と同期に残さない」が有効なとき、受信テキストを `CF_UNICODETEXT` と一緒に次の形式で置く（Windows の文書化された形式）。

- `ExcludeClipboardContentFromMonitorProcessing`（クリップボード監視ソフトに無視させる）
- `CanIncludeInClipboardHistory` = DWORD 0（`Win+V` の履歴に残さない）
- `CanUploadToCloudClipboard` = DWORD 0（クラウド同期しない）

どちらの場合もアプリ終了後もクリップボードに残る（`SetDataObject(…, copy: true)`）。

### 7.2 多重起動

`Local\` の名前付き Mutex でセッションごとに 1 つに限る。2 つ目の起動は名前付きイベントで既存のインスタンスに知らせ、`AllowSetForegroundWindow` で前面化の権利を渡して何も表示せずに終了する。既存のインスタンスは QR ウィンドウを前面に出す。

### 7.3 QR ウィンドウ

タイトル「Hatoclip – 接続用QRコード」。構成：

- 案内文「iPhone のカメラで読み取り、表示されたリンクを開いてください」
- QR コード（`http://<LAN IPv4>:<port>/#k=<key>`）。LAN の IP が見つからないときだけ `.local` 版を QR にする
- 接続の確認欄（緑の太字）。普段は空で、スマホが正しいキーでページを開くと「✓ スマホが接続しました」になる
- 「URL（IP アドレス）」と「URL（PC 名 .local 版）」の 2 行。それぞれ「コピー」ボタン付き
- ネットワーク診断（7.4）
- 「キーを再生成」「閉じる」ボタン

ふるまい：

- 初回起動時（設定の `firstRunShown` が false）に自動で表示し、表示後に `firstRunShown` を true にする
- 閉じても破棄せず隠すだけ。表示時は一瞬だけ最前面にして前面化する
- 表示直後のフォーカスは「閉じる」ボタン（キー入りの URL を選択状態で始めない）
- 「✓ スマホが接続しました」は、ウィンドウが表示されている間に `/api/ping` が成功したときだけ出す（6.2）。ウィンドウを表示し直したときと、キーが変わったとき（再生成）に消す。接続してもウィンドウは自動では閉じない。表示・非表示でウィンドウの大きさが変わらないよう、1 行分の高さを最初から確保している
- `.local` 名は DNS ホスト名（`Dns.GetHostName()`、小文字）を使う。`MachineName` は NetBIOS 名で 15 文字に切られるため
- QR は 1 モジュールが整数ピクセルになるように縮尺を決める（カメラで読みやすいように）

**見た目**：

- 配色はスマホのページ（`Web/style.css` の CSS 変数）と同じ値を `Theme` にまとめている（背景・カード・入力欄・文字・薄い文字・枠線・アクセント・フォーカスなど）。警告の色（淡い琥珀色）と接続確認の淡い緑だけは PC 側で定義。フォントは Yu Gothic UI（無ければ Segoe UI）。寸法（余白・角丸・ボタンの高さ）も `Theme` と `QrWindow` の定数で、96 DPI の論理ピクセル
- 構成：上に鳩のマーク（ページの SVG と同じ形を GDI+ で描画）と「Hatoclip」、案内文。その下に角丸のカード 1 枚で、左に QR（白い角丸の台紙。ダークでも白地に黒）、右にネットワーク診断と接続確認、下に URL の 2 行。カードの下に「キーを再生成」（枠線だけの控えめなボタン、左）と「閉じる」（アクセント色、右）
- 部品は自前描画（`RoundedButton` は `Button` の派生なので Enter / Space、`CancelButton`、読み上げの役割はそのまま）。キーボード操作時はボタンにフォーカスの輪を描く
- URL 欄は枠なしの読み取り専用 `TextBox` を角丸の欄に入れたもの。フォーカスが無いときに長い URL は末尾を「…」で省略し、フォーカスすると全文に戻して全選択する。コピーは常に全文
- 診断の警告は淡い琥珀色の角丸の囲みに、先頭の「⚠」を三角のアイコンとして描く（文字列そのものは変えていない。読み上げは全文）。問題なしは緑の丸、種類不明は灰色の丸、末尾の注記は小さな薄い文字
- ライト／ダークは Windows の「既定のアプリ モード」（`HKCU\…\Themes\Personalize` の `AppsUseLightTheme`）に従い、起動中の切り替えにも追従する（`SystemEvents.UserPreferenceChanged`）。タイトルバーは DWM の `DWMWA_USE_IMMERSIVE_DARK_MODE` で合わせる。開発用に環境変数 `HATOCLIP_THEME=light|dark` で固定できる。メッセージボックスは Windows 標準のまま
- DPI：アプリは Per-Monitor V2（csproj の `ApplicationHighDpiMode`）。QR ウィンドウは自動スケーリングを使わず、ウィンドウの DPI から配置・フォント（ピクセル指定）・角丸・線の太さを計算し直す（DPI の違うモニターへ移したときも）。QR 画像もその大きさで描き直す。ウィンドウが作業領域より高くなる場合は QR を小さくする（最小 200 論理ピクセル）。100 %・125 %（実モニター）と 150 %・200 %（同じ計算を強制した描画）で確認
- Windows 11 ではウィンドウの角を丸くし、トレイメニューも小さな角丸と DWM の枠線にする。Windows 10 では属性の設定が失敗するだけで、四角のまま（メニューは自前の枠線）

**トレイメニューの見た目**：`TrayMenuRenderer` で、カード色の背景、選択中の項目は淡いアクセント色の角丸、チェックはアクセント色の線、区切り線は枠線の色、項目の上下に余白。項目と順序は 7.1 のとおり。

**自動更新**：`ConnectionMonitor` が `NetworkChange.NetworkAddressChanged` / `NetworkAvailabilityChanged` のイベントと、10 秒ごとのポーリングで IP・ポート・キー・診断を計算し直す。前回と違うときだけ QR ウィンドウとツールチップを更新する。ウィンドウを表示したときも計算し直す。

**LAN IP の選択**（`NetworkInfo.SelectLanAddress`）：

1. 動作中（Up）のインターフェースのうち、ループバック・トンネル・PPP を除く
2. 名前か説明に次の語を含むものは仮想・VPN アダプターとして除く（大文字小文字は区別しない）：`Hyper-V`, `vEthernet`, `WSL`, `VirtualBox`, `VMware`, `TAP`, `Tailscale`, `ZeroTier`, `Wintun`, `WireGuard`, `OpenVPN`, `Bluetooth`, `Npcap`, `Loopback`, `Wi-Fi Direct`
3. ループバックとリンクローカル（169.254.x.x）以外の IPv4 アドレスを持つものが候補
4. 優先順：IPv4 の既定ゲートウェイあり ＞ 物理的な種類（Ethernet / Wi-Fi）＞ ルーティングテーブルで外向きの最良経路（`GetBestInterface` によるローカルな経路検索。パケットは送らない）

候補と除外したアダプター名は起動時（と IP が見つからないとき）にログに出す。

### 7.4 ネットワーク診断

すべて読み取りのみで、失敗したら「不明」として扱う。

- **ネットワークの種類**：Network List Manager の COM API（手書きの最小限の相互運用定義）で、選んだアダプターのネットワークのカテゴリ（パブリック／プライベート／ドメイン）を読む。アダプターが対応付けられなければ、接続中のネットワークのうち最も信頼度の低いものを使う
- **ファイアウォール**：レジストリ `HKLM\SYSTEM\CurrentControlSet\Services\SharedAccess\Parameters\FirewallPolicy` を読む。現在のプロファイルでファイアウォールが無効なら問題なし。有効なら `FirewallRules` から、有効・受信・現在のプロファイルに該当・TCP を含む規則を探し、この exe のパスに一致する許可規則（またはアプリ指定のない、このポートを含む許可規則）があれば許可済み、この exe へのブロック規則があればブロック（ブロックが優先）。グループポリシーやサードパーティ製ファイアウォールの規則は見えないので、表示は「可能性があります」にとどめる

表示する内容：

| 状態 | 表示 |
|---|---|
| LAN の IP なし | ⚠ LAN の IP アドレスが見つかりません。Wi-Fi または有線 LAN に接続してください。 |
| プライベート／ドメイン | ネットワーク: プライベート ✓ ／ ネットワーク: ドメイン ✓ |
| パブリック | ⚠ このネットワークは「パブリック」になっています。… と、プライベートに変更する手順 |
| 種類不明 | ネットワーク: 種類を確認できませんでした |
| 許可規則なし／ブロック | ⚠ ファイアウォールでこのアプリが許可されていない可能性があります。 |

常に末尾に、ファイアウォールの確認で「許可」を選んだかの確認と、ゲスト用 Wi-Fi では接続できない旨の注記を出す。ファイアウォールの設定はアプリから変更しない（変更には管理者権限が要り、方針にも反するため）。

### 7.5 自動起動

`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` に値名 `Hatoclip`、値は引用符付きの exe パス。管理者権限は不要。起動時に、登録済みのパスが現在の exe と違い、かつその exe がもう存在しなければ（exe を移動した場合）今の場所に書き直す。登録先の exe が残っている場合は別のコピー（開発用ビルドなど）を起動しただけとみなし、書き換えない。

## 8. スマホ側ページ

日本語 UI、モバイルファースト、ライト／ダーク対応（`prefers-color-scheme`）。鳩のマークはインライン SVG で、トレイ・PWA アイコンと同じ形。

### 8.1 画面構成

上から：

1. **ヘッダー**：鳩マークと「Hatoclip」、接続状態（「● <PC名> に接続中」など）と「再接続」ボタン、お知らせ欄
2. **接続キー未設定・不一致のカード**（必要なときだけ表示）：「PCのQRコードを読み取ってください」または「接続キーが一致しません。PCのQRコードを読み直してください」と、接続キーの貼り付け欄（8.3）
3. **PC → スマホ**：「PCのクリップボードを取得」→ 読み取り専用の欄に表示 →「コピー」
4. **スマホ → PC**：大きめのテキスト欄（長押しでペーストしやすい大きさ）と「PCに送信」。成功で欄を空にして「PCに届けました」（飛ぶ鳩のアイコン付き）
5. **折りたたみ「ショートカットでもっと便利に（任意）」**（8.4）
6. フッター「このページはPCと同じWi-Fi内でのみ動作します。外部には何も送信しません。」

**接続状態の表示**：状態の文字の前に小さな丸を付け、色で状態を示す（接続中は緑、エラーは赤、確認中は灰色。ライト／ダークとも CSS 変数の `--ok` / `--error` / `--muted`）。丸は CSS の疑似要素で、読み上げには含まれない。「再接続」ボタンは、直前の接続確認がやり直しで直る可能性のある理由（PC に届かない、429、その他のエラー）で失敗したときだけ出す。接続中・キー未設定・キー不一致（401）のときは出さない。確認中は押せない状態にする。

**キーが使えない間はカードを隠す**：キーが保存されていないとき、または `/api/ping` が 401（キー不一致）のときは、3〜5 のカードを隠し、2 のカードだけを出す。PC に届かないときと 429 のときは、今までどおり 3〜5 も表示する（キー自体は正しい可能性があるため）。確認中は直前の表示のまま。取得・送信の操作が 401 になった場合は、そのカードにエラーを出すだけでカードは隠さない（入力中のテキストが見えなくならないように）。

リクエストは 10 秒でタイムアウトし、`cache: 'no-store'` で送る。

### 8.2 キーの受け取りと保存

- QR から開いたとき、フラグメント `#k=` からキーを読み、すぐにフラグメントを消す
- 保存先は `localStorage`（キー名 `hatoclip.key`）。使えない環境ではページを開いている間だけメモリに持つ
- **保存済みのキーと違うキーを受け取ったとき**は、そのキーで `/api/ping` を呼び、PC が受け付けた場合だけ置き換える。リンク 1 つで動いている接続を壊されないようにするため。401 なら「読み取ったQRコードの接続キーは、このPCのものと一致しませんでした。現在の接続をそのまま使います」と表示して元のキーを使い続ける。PC に届かない場合も元のキーのまま
- ページを開いたまま別の QR を読んだ場合（`hashchange`）も同じ処理をする

### 8.3 ホーム画面アプリ用のキー貼り付け

ホーム画面に追加した PWA は Safari とストレージが別なので、Safari で接続済みでもキーが引き継がれない。そのため未接続カードにキーの貼り付け欄を置き、Safari 側の「ショートカットでもっと便利に」でコピーしたキーを貼れるようにしている。

- キーそのものでも、`#k=` を含む接続 URL 全体でも受け付ける
- 保存済みのキーを置き換える場合は先に `/api/ping` で確かめ、401／429 なら理由を表示して元のキーを残す。PC に届かない場合は利用者の明示的な操作なので保存する

### 8.4 ショートカット欄

- 送信用・受信用ショートカットの追加リンク。URL は PC の `config.json` の `shortcutSendUrl` / `shortcutReceiveUrl` を `/api/ping` の応答で受け取る（接続確認のたびに反映）。http/https の URL でない間は「（準備中）」と表示して押せない
- ショートカットの「読み込み時の質問」に貼る「接続先URL」（`location.origin`）と「接続キー」（既定は伏せ字。「表示」で切り替え）を、それぞれ「コピー」ボタン付きで表示
- 背面タップへの割り当て手順（設定 → アクセシビリティ → タッチ → 背面タップ）

### 8.5 コピーとペースト

- ページは http（非セキュアコンテキスト）なので `navigator.clipboard` が使えない。コピーは一時的な `textarea` を選択して `document.execCommand('copy')` で行う（iOS でも動く方法）。失敗したら長押しでのコピーを案内する
- `window.isSecureContext` かつ `navigator.clipboard.readText` があるときだけ「ペーストして送信」ボタンを出す。現状の http では表示されない（HTTPS 化した場合に備えた分岐）

### 8.6 エラーメッセージ

文言で遊ぶのは成功時だけで、エラーは分かりやすさを優先する。

| 状況 | 表示 |
|---|---|
| 接続できない・タイムアウト | PCに接続できません。同じWi-Fiに接続しているか、PCでHatoclipが起動しているか確認してください |
| 400 `empty` | テキストを入力してください |
| 401 | 接続キーが一致しません。PCのQRコードを読み直してください |
| 403 | PCの設定で取得が許可されていません |
| 413 | テキストが大きすぎます（1MBまで） |
| 429 | 認証に失敗した回数が多いため、しばらく待ってから再度お試しください |
| 503 | PCのクリップボードが使用中です。もう一度お試しください |
| その他 | 送信に失敗しました（HTTP <番号>）／取得に失敗しました（HTTP <番号>） |
| 取得結果がテキスト以外／空 | PCのクリップボードはテキストではありません／PCのクリップボードは空です |

### 8.7 PWA

`manifest.webmanifest`（`display: standalone`、`start_url: /`）と、192 px・512 px のアイコン、180 px の `apple-touch-icon` を持つ。アイコンは `tools/make-web-icons.ps1` で生成する。Service Worker は使わない（http では登録できない）。

## 10. 設定ファイルとログ

### 10.1 `config.json`

場所は `%LOCALAPPDATA%\Hatoclip\config.json`。

| キー | 既定値 | 意味 |
|---|---|---|
| `key` | 初回に生成 | 接続キー（16 進 32 文字）。32 文字未満なら作り直す |
| `port` | `52817` | 待ち受けポート。1024〜65535 以外なら既定値に戻す |
| `allowGet` | `true` | スマホからの取得（GET `/api/clipboard`）を許可 |
| `showPreview` | `true` | 受信通知に内容の先頭を表示 |
| `excludeFromHistory` | `false` | 受信テキストをクリップボード履歴・クラウド同期から除外 |
| `firstRunShown` | `false` | 初回の QR ウィンドウ自動表示が済んだか |
| `shortcutSendUrl` | `""` | 送信用ショートカットの iCloud リンク |
| `shortcutReceiveUrl` | `""` | 受信用ショートカットの iCloud リンク |

- 読み込みは起動時だけ。以後はメモリ上の設定を使い、トレイメニューで変更するたびに書き直す（一時ファイルに書いてから置き換える）。そのため手で編集するときはアプリを終了しておく
- 古い版の設定に後から追加したキー（`showPreview`, `excludeFromHistory`, `shortcutSendUrl`, `shortcutReceiveUrl`）が無ければ、既定値を補って書き戻す（利用者がすべての設定を見られるように）
- 読めたが JSON として解釈できない場合は、元のファイルを `config.json.bak`（既にあれば `config.<yyyyMMdd-HHmmss>.bak`）に移してから新しい設定（新しいキー）を作り、起動後に「設定ファイルが壊れていたため、新しい設定を作成しました。…」と知らせる。ファイル自体が読み書きできない場合はエラーを表示して終了する

### 10.2 ログ

- 場所：`%LOCALAPPDATA%\Hatoclip\logs\hatoclip-YYYYMMDD.log`（UTF-8）
- 起動時に 14 日より前の日付のファイルを削除
- 1 日のファイルは 5 MB まで。超えたら 1 行の警告を書いて、日付が変わるまで以降を捨てる（大量のリクエストでディスクを埋めない）
- アプリを動かしたままログを開いたり削除したりできる共有モードで開く
- 記録するもの：起動・終了、設定の変更、接続状態の変化（IP、インターフェース、ポート、ネットワークの種類、ファイアウォール判定）、リクエストの「メソッド パス → ステータス（送信元 IP）」、認証失敗とブロック、エラー。Kestrel のログは警告以上だけを合流させる
- **接続キーとクリップボードの内容は記録しない**。リクエストはパスだけでクエリ・ヘッダー・本文は出さない。接続状態の文字列表現からもキーを除いている（再生成は「key=(regenerated)」とだけ記録）
- ログを書けなくてもアプリは止めない

## 11. セキュリティ上の考慮と受容したリスク

対策：

- キー必須の API、定数時間比較、IP 単位のロックアウト（5 章）
- キーは URL フラグメントで受け渡し、ログに残さない
- カスタムヘッダー認証と CORS 非対応による CSRF・DNS リバインディング対策
- CSP・`nosniff`・`no-referrer`・`frame-ancestors 'none'`、API 応答の `no-store`
- 1 MB の本文上限、ログの日次上限、レート制限表の件数上限
- 空の本文でクリップボードを消さない
- PC のクリップボードが読まれたらトレイアイコンで分かる。取得自体を無効にもできる
- 受信通知のプレビューと、クリップボード履歴・クラウド同期への残存を利用者が選べる
- 待ち受けは IPv4 のみ、ポートは排他的に確保

受容しているリスク：

- **LAN 上は平文の HTTP**。キーは毎回のリクエストヘッダーで、クリップボードの内容は本文で暗号化されずに流れる。同じネットワークの他人が盗聴できるので、カフェなど信頼できない Wi-Fi では使わない前提（README に明記）
- **キーは全端末で 1 つ**で、有効期限が無い。端末ごとの取り消しはできず、再生成すると全端末がつなぎ直しになる
- ファイアウォール診断はベストエフォート（グループポリシーや他社製ファイアウォールは判定できない）
- コード署名をしていないので初回に SmartScreen が出る（回避手順は README）
- プロジェクト自体のライセンスは未定

## 12. 配布

- `tools/publish.ps1` で win-x64 と win-arm64 を発行し、それぞれ `publish\Hatoclip-<version>-<rid>.zip` を作る。zip の中身は `Hatoclip.exe` と `THIRD-PARTY-NOTICES.txt`（同梱する .NET ランタイムと QRCoder のライセンス表示。[THIRD-PARTY-NOTICES.txt](../THIRD-PARTY-NOTICES.txt)）
- 発行設定は `src/Hatoclip/Properties/PublishProfiles/win-x64.pubxml` / `win-arm64.pubxml`：self-contained、単一ファイル、ネイティブライブラリも同梱（展開フォルダーを作らない）、単一ファイルの圧縮あり
- **トリミングと ReadyToRun はしない**。WinForms と ASP.NET Core はトリミングに対応していない。ReadyToRun はサイズがおよそ 2 倍になる
- フレームワークの衛星リソースアセンブリは英語のみ（UI 文言はアプリ内の文字列のため）。Release ビルドはシンボルを含めない
- バージョンは csproj の `<Version>`（現在 1.0.0）。コード署名はしない
- インストーラーは無い。exe を好きな場所に置いて起動する。アンインストールは README の手順（自動起動の解除、exe と `%LOCALAPPDATA%\Hatoclip` の削除）

## 13. テスト

`tests/Hatoclip.Tests`（xUnit v3）。リポジトリのルートで `dotnet test` を実行する（`global.json` で Microsoft.Testing.Platform を指定）。LAN・実際のクリップボード・ログファイルは使わない。

| テストクラス | 対象 |
|---|---|
| `HttpApiTests` | 実際の Kestrel を 127.0.0.1 の空きポートで起動し、HTTP で検証：ping と接続イベント（401 や他の API では出ない）、キーなし・不一致の 401（未知の `/api` パスも）、繰り返しの失敗で 429 でも正しいキーは通る、OPTIONS が CORS なしの 204 で失敗に数えない、JSON・日本語・絵文字・改行の POST、`excludeFromHistory` の受け渡し、400（`empty` / `bad-request`）でクリップボードを変えない、413、GET と取得イベント、403、503、セキュリティヘッダーとキャッシュ |
| `PortFallbackTests` | 設定のポートが使用中なら別のポートで起動し、設定ファイルは変えない。空けば次回は元のポート |
| `AuthRateLimiterTests` | しきい値、IP ごとの集計、IPv4 射影アドレス、ブロックの期限、ウィンドウ外の失敗の忘却、成功時の扱い、リセット、整理と件数上限 |
| `ConfigStoreTests` | 初回生成（128 bit の 16 進キー、既定値）、往復、古い設定の書き戻し、壊れたファイルのバックアップ、不正なキー・ポートの置き換え、キー再生成 |
| `FirewallRuleTests` | ファイアウォール規則文字列の判定（有効・方向・プロファイル・プロトコル・パス・ポート範囲・ブロック優先・不正な文字列） |
| `PureHelperTests` | ショートカット URL の検査、仮想アダプターの除外と候補の順序、接続 URL のフラグメント、通知プレビュー、履歴除外のクリップボード形式、埋め込みアイコン |
| `ThemeTests` ほか | テーマ指定の解釈、`AppsUseLightTheme` の判定、論理ピクセルの換算、配色がページと同じ値か、URL の「…」省略（サロゲートペアを切らない）、色の混合 |

テストのための継ぎ目：

- `IClipboardService`：サーバーは実際のクリップボードの代わりに `FakeClipboard` を使える（使用中の状態も再現）
- `HatoclipServer` の待ち受けアドレス引数：テストはループバックで待ち受けるので、ファイアウォールの確認が出ない
- `AuthRateLimiter` の `TimeProvider`：時計を進めてブロックの期限を検証
- `ConfigStore` はファイルパスを受け取るので一時フォルダーで試せる
- `Log.Enabled`（テストでは無効）、`InternalsVisibleTo` による内部ヘルパー（`EvaluateRules`, `OrderCandidates`, `BuildReceivedMessage` など）の直接テスト

UI（トレイ、QR ウィンドウ）、実際のクリップボード、Network List Manager、スマホのページは自動テストの対象外。

## 15. 満たしている要件

- 新しい Windows PC に exe を置いて起動し、スマホで QR を読むだけで双方向にテキストをやり取りできる（管理者権限・追加インストール不要。ファイアウォールの確認で「許可」を選ぶ必要はある）
- キーを持たない端末からの API 呼び出しは 401（ブロック中は 429、OPTIONS は 204）で、クリップボードに触れない
- 日本語・絵文字・改行を含むテキストを UTF-8 で送受信できる（テストで確認）
- PC の IP が変わると QR が自動で更新され、読み直せば接続できる
- iOS ショートカットから JSON の POST と GET ができる形の API になっている
- アプリを終了するとサーバーが停止し、ポートが解放される

## 16. 対象外

- 画像・ファイルの送受信
- 送受信の履歴
- インターネット越しの接続、HTTPS 化
- 自動同期（クリップボードを監視して自動で送る機能）
- 端末ごとのキー、キーの有効期限
- サブディスプレイ機能（将来の拡張候補。HTTP サーバーと認証はクラスとして分けてあり、`/api` グループにエンドポイントを足せば同じ認証が掛かる）

## 17. 確認済みの事項・既知の制約

- self-contained 単一ファイルの exe は、x64 版でおよそ 58 MB、arm64 版でおよそ 57 MB
- arm64 版はビルドのみで、実機では動かしていない
- `<PC名>.local` が名前解決できるかはネットワーク（ルーターや端末）に左右される。そのため QR は IP アドレス版の URL にし、`.local` 版は代わりの URL として併記している
- 初回起動時に Windows ファイアウォールの確認が出る。ここで許可しないとスマホから接続できない。exe を別のフォルダーに移すと再び出ることがある。アプリはファイアウォールの設定を変更しない
- PC がスリープしている間、ゲスト用 Wi-Fi やプライバシーセパレーターが有効な Wi-Fi では接続できない
- 代わりのポートで起動した回は、ブックマークやショートカットの URL が合わなくなる（QR の読み直しが必要）
